# TF-анализ (SEO)

Сравнивает текст своей страницы с конкурентами из ТОП-10 по запросу: количество слов/символов и частоту словоформ (по леммам), чтобы показать недо- и переоптимизированные слова.

Многие сайты и сама выдача Google/Яндекс блокируют автоматический парсинг, поэтому исходные HTML-страницы (свою и конкурентов) вы сохраняете вручную из браузера — так гарантированно проходит любая защита от ботов. Анализ (лемматизация, TF-статистика, сравнение) делается уже локально по этим файлам.

## Установка

1. Скачайте бинарник Yandex Mystem для вашей ОС с официальной страницы: https://yandex.ru/dev/mystem/
2. Положите его в `tf_analysis/bin/mystem.exe` (Windows) или `tf_analysis/bin/mystem` (Linux/macOS).
   Либо укажите путь через переменную окружения `MYSTEM_PATH`.
3. Зависимости отдельно ставить не нужно — модуль использует `puppeteer`/`puppeteer-extra` из корня проекта.

## Использование

1. Сами определите ТОП-10 конкурентов по запросу (в Google/Яндекс вручную).
2. Для каждого запроса создайте папку `tf_analysis/input/<любое-имя-папки>/` и положите в неё:
   - файл запроса — **любое имя, главное расширение `.txt`** (например `query.txt`, но подойдёт и `мой запрос.txt`): сам запрос, опционально + свои главные/LSI-слова (см. ниже). Если `.txt`-файлов в папке несколько — берётся первый по алфавиту, остальные игнорируются (с предупреждением в консоли);
   - `own.txt` — HTML-код вашей страницы;
   - остальные `*.txt` — HTML-код страниц конкурентов (любые имена, кроме `own.txt` и файла запроса `query.txt`).

   Страницы хранятся как `.txt` с HTML-кодом внутри. Файлы `*.html` перед запуском автоматически переименовываются в `*.txt` (старый файл запроса с любым именем при этом становится `query.txt`).

   Как сохранить страницу: откройте её в браузере → `Ctrl+S` → **«Веб-страница, только HTML»** → переименуйте в `.txt` (или оставьте `.html` — скрипт переименует сам). Если часть контента подгружается скриптами, надёжнее скопировать код из панели разработчика (Elements → `<html>` → Copy outerHTML).

   Формат `query.txt` — первая строка это запрос, дальше опционально секции `[Главные]` и `[LSI]`
   со словами/фразами **в исходной форме** (мы сами их лемматизируем и сопоставим с текстом страниц),
   через запятую или по одной на строку:
   ```
   защита сайта от ddos

   [Главные]
   защита сайта, ddos атака

   [LSI]
   файрвол, хостинг, cdn, dns, трафик
   ```
   Слова из этих секций в итоговом отчёте попадают в колонку «Важность» (Главное/LSI) и
   всегда показываются, даже если реально встречаются реже, чем у 30% конкурентов (порог `LEMMA_MIN_COVERAGE_RATIO`
   для остальных, «органических» лемм, не применяется к вручную помеченным).

   Пример:
   ```
   tf_analysis/input/ddos-protection/
     query.txt
     own.html
     competitor1.html
     competitor2.html
     ...
   ```
3. Запустите:
   ```
   node tf_analysis/index.js
   ```
4. Результаты — все в одной папке `results/<дата проверки>/`. Файлы называются как папка `input/<...>/`, из которой взяты данные, + суффикс: `<имя папки>_результат.csv` (сравнение лемм) и `<имя папки>_summary.csv` (сводка по длине текста и списку страниц). Все задачи одного запуска `index.js` попадают в одну и ту же дату, даже если анализ нескольких запросов занял время.

   **Файл запроса необязателен.** Если в папке `input/<имя>/` нет `.txt` (или в нём нет запроса), запросом становится имя папки (без пометок в скобках и суффикса «Яндекс»/«Google»), а главные и LSI-слова скрипт определяет сам: центр темы — леммы запроса, а если их нет на страницах конкурентов — самые частотные слова ТОП-10. В колонке «Важность» они помечаются `Главное (авто)` и `LSI (авто)`. Всё, что вы задали вручную в `query.txt`, приоритетнее и авто-определение не затрагивает. Нужны только `own.html` и HTML-файлы конкурентов.

   Дополнительно для каждой задачи строятся **кластеры слов (темы)** алгоритмом KMeans (k подбирается автоматически по силуэту, seed фиксирован — результат воспроизводим):
   - `<имя папки>_кластеры.csv` — таблица «разбиение, кластер, тема, лемма, важность (Главное/LSI), среднее ТОП-10, покрытие, у вас». Два разбиения: «По словам (TF-IDF)» — леммы, которые встречаются на одних и тех же страницах, и «По LSI (SVD)» — кластеры в пространстве скрытых тем (усечённое SVD матрицы «лемма × страница»);
   - `<имя папки>_облако.png` и `<имя папки>_облако_LSI.png` — облака слов, раскрашенные по кластерам этих двух разбиений (размер — средняя частота у ТОП-10, «Главное» — жирным с подчёркиванием, «LSI» — курсивом). Рисуются через Puppeteer, дополнительных зависимостей нет.

   **LSI-слова определяются автоматически.** Разметка `[LSI]` в `query.txt` необязательна: скрипт строит LSI-пространство (SVD матрицы «лемма × страница ТОП-10») и берёт слова, наиболее близкие по смыслу к «центру темы» — леммам запроса и главным словам. Если слов запроса нет в текстах конкурентов, центром становятся самые частотные слова. Такие слова получают в колонке «Важность» значение `LSI (авто)`, вручную размеченные `[LSI]` остаются `LSI` и имеют приоритет. Порог близости, максимум слов и минимальное покрытие — `AUTO_LSI_*` в `config.js`.

   **Книга Excel.** В конце каждого запуска `index.js` все CSV папки результатов автоматически собираются в `results/<дата>/<дата>_все.xlsx`: одна вкладка на файл, плюс первая вкладка «Оглавление» с полными именами файлов (имена вкладок Excel ограничены 31 символом, длинные сокращаются с середины). Собрать книгу вручную: `node merge_to_xlsx.js` (последняя дата) или `node merge_to_xlsx.js 2026-10-06`. Использует библиотеку `exceljs`.

   Параметры (диапазон k, число LSI-компонент, макс. число слов в облаке) — в `config.js`. Нужно минимум 6 лемм, иначе кластеризация пропускается.

## Как это работает

1. `utils/inputFolders.js` — сканирует `input/*/`, находит файл запроса (любое имя, расширение `.txt`) + `own.html` + HTML конкурентов в каждой папке.
2. `lib/fetchPageText.js` — загружает HTML-код из файла в puppeteer (`setContent`), вырезает шум (nav/header/footer/script и т.п.), считает слова/символы.
3. `lib/lemmatizer.js` — лемматизирует текст через Mystem.
4. `lib/tfStats.js` — считает частоты лемм, агрегирует по конкурентам (мин/среднее/медиана/макс), сравнивает со своей страницей.
5. `utils/report.js` — сохраняет CSV с BOM (корректная кириллица в Excel).

## Альтернативный (не рекомендуемый) режим — автопарсинг

`lib/fetchTop10.js` умеет получать ТОП-10 напрямую из Google/Яндекс через `multi_search_parser`, а `fetchPageText.js` поддерживает и обычные URL, не только локальные файлы. Но многие сайты блокируют автоматические заходы, поэтому основной сценарий — ручная выгрузка HTML, описанная выше. `scripts/tasks.txt` и `utils/tasks.js` оставлены в проекте на случай, если понадобится вернуться к автопарсингу.
